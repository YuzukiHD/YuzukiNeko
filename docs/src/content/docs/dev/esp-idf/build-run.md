title: "Building, loading and running"
---

The ESP-IDF build product is not firmware that can be written to NOR; it is a RAM image linked at `0x40000000`. The flow below starts from an empty project and ends with xfel writing the image into PSRAM over FEL and executing it. Every command runs in a terminal with the [environment](setup.md) active.

## Project layout

A minimal project has three files:

```text
hello_f101/
  CMakeLists.txt
  main/CMakeLists.txt
  main/main.c
```

The top-level `CMakeLists.txt` must enable `MINIMAL_BUILD`; otherwise ESP-IDF adds every component under `components/` to the configuration, including Bluetooth, OpenThread and test components that do not apply to F101:

```cmake
cmake_minimum_required(VERSION 3.22)
include($ENV{IDF_PATH}/tools/cmake/project.cmake)
idf_build_set_property(MINIMAL_BUILD ON)
project(hello_f101)
```

`main/CMakeLists.txt` declares the application sources and the components it needs. Without `REQUIRES` only the default components are linked; add each driver that the application uses:

```cmake
idf_component_register(SRCS "main.c")
```

`main/main.c` is an ordinary ESP-IDF application:

```c
#include <stdio.h>

void app_main(void)
{
    printf("Hello from F101\n");
}
```

## Set the target

Run this for the first configuration or after changing the target:

```sh
IDF_SKIP_CHECK_SUBMODULES=1 IDF_COMPONENT_MANAGER=0 idf.py --preview set-target sun252i-f101
```

`--preview` is required because `sun252i-f101` is a preview target. `IDF_SKIP_CHECK_SUBMODULES=1` stops CMake from initializing every submodule again; `IDF_COMPONENT_MANAGER=0` disables the component manager, which this port does not use. The target can only be set in an empty build directory; after changing it, run `idf.py fullclean` or remove `build/`.

## Console configuration

The F101 default console is UART1, TX on PB0 (GPIO 32), RX on PB1 (GPIO 33), 115200 8N1, matching the YuzukiNeko serial port. The default comes from the F101 conditional default in `components/esp_stdio/Kconfig`.

The `f101_evb` console is UART3, TX on PE8 (GPIO 136), RX on PE9 (GPIO 137). On the EVB, run `idf.py menuconfig`, open `Component config → ESP-STDIO → Channel for console output`, select `Custom UART`, then `UART3`, and enter the two GPIOs. The corresponding `sdkconfig` lines are:

```text
CONFIG_ESP_CONSOLE_UART_CUSTOM=y
CONFIG_ESP_CONSOLE_UART_CUSTOM_NUM_3=y
CONFIG_ESP_CONSOLE_UART_TX_GPIO=136
CONFIG_ESP_CONSOLE_UART_RX_GPIO=137
```

## Build

F101S4 boards must also set `CONFIG_ESP_F101_PSRAM_MB` to 32; the default 16 matches F101S3. The value controls both the linker RAM length and the heap end, and must match the capacity initialized by the PSRAM helper. Change it in `idf.py menuconfig` under `ESP System Settings`, or write it directly to `sdkconfig`:

```text
CONFIG_ESP_F101_PSRAM_MB=32
```

Then build:

```sh
IDF_SKIP_CHECK_SUBMODULES=1 IDF_COMPONENT_MANAGER=0 idf.py build
```

The products land in `build/`:

| File | Content |
| --- | --- |
| `hello_f101.elf` | Complete image with symbols, entry `0x40000000` |
| `hello_f101.map` | Link map for section addresses and symbols |
| `bootloader/` | Not produced by a RAM build; its absence is normal |
| `hello_f101.bin` | Not generated by a RAM build; convert it manually |

## Make a loadable image

The `idf.py` `elf2image` step targets ESP chips and does not support F101, so a RAM build produces no `.bin`. Convert the ELF load segment to a raw binary with the toolchain's `objcopy`:

```sh
riscv32-esp-elf-objcopy -O binary build/hello_f101.elf build/hello_f101.bin
```

The first byte of the image is at `0x40000000`, and its length equals the ELF `LOAD` segment size. Check `VirtAddr` and `FileSiz` with `riscv32-esp-elf-readelf -l build/hello_f101.elf`; do not load it if the entry is not `0x40000000`.

## Prepare the PSRAM helper

`xfel ddr f101-s3` carries only S3 parameters and cannot initialize S4; S3 and S4 need different `dram_para` tables. Build `init_psram_efex_s3.bin` or `init_psram_efex_s4.bin` for the board as described in the global topic [PSRAM initialization and RAM boot](../../boot/psram-init.md); the commands below assume that file exists.

## Load and run through FEL

With the board in FEL, initialize PSRAM with the helper that matches the board. The example uses S3; replace the file with `init_psram_efex_s4.bin` on S4:

```sh
xfel version
xfel write 0x20000 init_psram_efex_s3.bin
xfel exec 0x20000
```

The serial port should print the `LPSRAM CLK`, `LPSRAM Type`, `LPSRAM SIZE` and `LPSRAM simple test OK.` lines matching the table, then the helper returns to FEL. Running `xfel version` again and seeing `AWUSBFEX ID=0x00193700(F101)` proves the return. Do not run `xfel ddr` before the helper.

Then write and run the ESP-IDF image:

```sh
xfel write 0x40000000 build/hello_f101.bin
xfel exec 0x40000000
```

`xfel write` needs no erase first because it writes PSRAM, not NOR. `xfel exec` sets the PC to `0x40000000` and hands over; the USB FEL device then disappearing from the host is normal.

## Expected output

The serial port at 115200 8N1 should show something like the following. The helper size line is 16 MB on S3 and 32 MB on S4; timestamps and heap sizes vary with the application:

```text
LPSRAM type detection done.
LPSRAM Type = APS128M
LPSRAM SIZE = 16 MB
LPSRAM simple test OK.
ESP-ROM:sun252i-f101-fel
Build:Nov 22 2026
rst:0x1 (POWERON),boot:0x0 (FEL_DOWNLOAD)
I (4045) cpu_start: Pro cpu up.
I (4048) cpu_start: Pro cpu start user code
I (4052) cpu_start: cpu freq: 600000000 Hz
I (4055) heap_init: Initializing. RAM available for dynamic allocation:
I (4062) heap_init: At 400136F0 len 00FEC910 (16306 KiB): RAM
I (4076) spi_flash: flash id 0x852018, 16 MiB
I (4080) main_task: Calling app_main()
Hello from F101
```

`ESP-ROM:sun252i-f101-fel` is the port's startup banner, not native chip ROM output. After the application calls `esp_restart()` the chip re-enters FEL and the image is gone; power cycling also returns to FEL unless NOR contains a bootable image.

## Rebuilding and cleaning

Run `idf.py build` again after source changes. CMake reconfigures automatically after `sdkconfig` changes; after a target or component dependency change use:

```sh
idf.py fullclean
IDF_SKIP_CHECK_SUBMODULES=1 IDF_COMPONENT_MANAGER=0 idf.py --preview set-target sun252i-f101
```

Give every application its own project directory and `build/`. Do not mix an F101 build directory with an ESP32 target or another ESP-IDF version.

## Flashing and monitoring

F101 has no flashing runner for `idf.py flash` and no boot chain from NOR, so `idf.py flash` is unavailable. `idf.py monitor` calls esptool to reset the chip and is equally unsuitable for the FEL flow; view serial output with ThunderWorkbench, `picocom` or another 115200 8N1 terminal.

To reload, enter FEL again, rerun the SyterKit helper (`write 0x20000` + `exec 0x20000`), then write and execute the image. xfel installation, udev permissions and the Windows driver are in [FEL tools](../../boot/fel.md).
